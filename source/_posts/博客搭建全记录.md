## 这篇写什么

这篇记录我把博客从零搭起来的过程，主要写技术选型、环境准备、安装步骤和后续配置。内容不追求官方文档式完整，重点是把我实际走过的流程写清楚，方便自己以后重搭，也给后来的人做参考。

---

## 技术选型

我最后用的是这套：

- Hexo 8.1.1
- AnZhiYu 主题
- GitHub Pages 托管

选择这套的原因很实际：

- Hexo 是静态博客，部署简单
- 主题生态成熟
- GitHub Pages 免费，够用

如果只是做个人博客、学习记录和技术笔记，这套方案基本够了。

---

## 环境准备

开始之前，本地需要有：

- Node.js
- npm
- Git

可以先检查版本：

```bash
node -v
npm -v
git --version
```

如果这三样都正常，后面安装 Hexo 会顺很多。

---

## 初始化 Hexo 项目

先全局安装 Hexo CLI：

```bash
npm install -g hexo-cli
```

然后初始化博客：

```bash
hexo init my-blog
cd my-blog
npm install
```

本地预览：

```bash
hexo server
```

这时候访问 `http://localhost:4000`，默认页面就能起来。

---

## 安装主题

我这里用的是 AnZhiYu。

安装命令：

```bash
git clone https://github.com/anzhiyu-c/hexo-theme-anzhiyu.git themes/anzhiyu
```

然后在站点根目录的 `_config.yml` 里把主题改成：

```yaml
theme: anzhiyu
```

主题依赖也要补上：

```bash
npm install hexo-renderer-pug hexo-renderer-stylus
```

这一步做完之后，主题基本就能跑起来。

---

## 基础配置

主要会改两个配置文件：

- `_config.yml`
- `_config.anzhiyu.yml` 或主题配置文件

站点级别一般要先把这些配好：

```yaml
title: Echo's Blog
description: 个人学习记录
author: Echo
language: zh-CN
url: https://yourname.github.io/repo
root: /repo/
```

这里最容易出问题的是 `url` 和 `root`。

如果你部署在 GitHub Pages 仓库子路径下，比如：

```text
https://用户名.github.io/My_Blog/
```

那 `root` 就必须是：

```yaml
root: /My_Blog/
```

这一项配错，后面很多静态资源和页面跳转都会出问题。

---

## 插件安装

我实际装过这些插件：

```bash
npm install hexo-deployer-git
npm install hexo-tag-aplayer
npm install hexo-butterfly-envelope
```

分别对应：

- GitHub 部署
- 音乐播放器
- 评论区信封样式

Hexo 项目很容易出现“本地能跑，换电脑就缺依赖”的情况，所以装过的插件最好都记下来。

---

## 部署到 GitHub Pages

生成静态文件：

```bash
hexo clean
hexo generate
```

部署：

```bash
hexo deploy
```

如果你在 `package.json` 里配了脚本，也可以直接用：

```bash
npm run deploy
```

这一步的前提是 `_config.yml` 里的 `deploy` 配置正确，比如：

```yaml
deploy:
  type: git
  repo: https://github.com/yourname/repo.git
  branch: gh-pages
```

## 实际使用里我比较在意的几块

搭完之后，我主要花时间处理的是这些：

- 顶部导航
- 侧边栏信息
- 评论系统
- 音乐播放器
- 页面样式细节

AnZhiYu 的可配项很多，优点是能改的地方多，缺点是出问题时排查范围也更大。所以建议一开始不要一次性改太多，先保证站能稳定运行，再慢慢加功能。

## 这套方案的优点和问题

### 优点

- 成本低
- 部署快
- 静态页面访问速度可以
- 主题和插件比较丰富

### 问题

- 配置项多，容易改乱
- 子路径部署时路径问题很多
- 主题升级后容易和自定义修改冲突

如果只是轻量使用，优点大于问题；如果改动很多，后期维护成本会明显上来。

---

## 我后来总结的几个经验

### 1. 子路径部署一定要先把 `root` 配对

这件事值得单独说一次。很多“页面 404”“资源丢失”“脚本失效”，根本原因都不是代码本身，而是路径没配对。

### 2. 主题尽量不要无脑直接改核心文件

如果后面升级主题或者换设备，很容易忘掉自己改过哪些东西。能用额外覆盖文件处理的，就尽量不要直接散改。

### 3. 每改完一个大功能就先 `generate` 一次

不要攒一堆修改最后一起看，不然出问题时很难定位到底是哪一步弄坏的。

---

## 总结

这次搭博客本身不算复杂，真正麻烦的是后面的配置、路径和自定义细节。

如果只是想尽快把博客搭起来，Hexo + AnZhiYu + GitHub Pages 是一套可以直接上手的方案。  
如果后面还要做很多魔改，那最好从一开始就把配置、依赖和修改记录整理好，不然后期维护会比较累。
